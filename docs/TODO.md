# 后续待办

更新：2026-10-20。当前已接通标准缓存加载、两阶段训练、恢复与评测；真实数据准备和四卡验证尚未完成。输入格式见 [缓存契约](CACHE.md)。

按以下顺序推进，先用少量真实样本跑通流程，再扩大规模。

- [ ] **盘点服务器原料（CPU / 磁盘）**：检查已有数据库、结构文件和历史处理结果，记录版本与哈希，只补下载缺失数据。
- [ ] **补齐清洗脚本（CPU）**：统一化学身份、单位和终点，去重并核验药理方向、实验条件与引用；缺失标签不补零，无测量不造阴性。
- [ ] **审核结构与残基映射（CPU）**：核对物种、构建体、突变和生物学装配，按链映射到完整序列，记录不可用样本及排除原因。
- [ ] **生成并冻结划分（CPU）**：按既定序列聚类及同源规则划分 train / val / test / external；两阶段共用划分，PIEZO 全家族隔离，检查跨来源泄漏。
- [ ] **准备模型输入（主要 CPU）**：生成独立候选口袋、稀疏残基图、分子构象和固定几何查询；测试配体坐标不参与候选口袋生成。
- [ ] **补齐特征提取与缓存构建（GPU + CPU）**：冻结 ProtBert/ChemBERTa，按唯一药物和蛋白分片提取；长序列使用重叠窗口，按缓存契约写入张量、版本和样本清单。
- [ ] **真实小子集验收（CPU + GPU）**：检查身份、映射、标签 mask 和批处理，跑通预训练、热身、微调、保存、恢复与独立评测。
- [ ] **四卡运行检查（GPU）**：用真实批次验证 DDP / AMP，测显存、吞吐和 I/O，再确定微批量、累积步数及训练耗时。
- [ ] **正式训练与对照（GPU）**：冻结数据和配置，完成两阶段训练、三组 seed 与必要对照，汇总独立测试指标，随后开展 PIEZO 候选筛选与结果导出。

前五步主要消耗 CPU、内存和磁盘；大模型特征提取与训练主要使用 GPU。完整数据准备脚本仍需补齐，不能直接把原始数据库交给训练入口。
